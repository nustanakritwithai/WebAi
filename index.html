Ownership

ไม่ให้ agent framework หลายตัวแย่งกันเป็นเจ้าของ state เดียวกัน

CONTROL

AI CPU

Task state machine, model routing, context budget, permissions, retry/escalation และ policy ของระบบ

DO

OMP

Coding worker หลัก: อ่าน repo, แก้ไฟล์, ใช้ shell/LSP/browser และส่งผลกลับเป็น structured result

KNOW HOW

ECC

เลือก rules/skills ที่เกี่ยวข้อง, ทำแผน, review, security checklist และ acceptance criteria

REMEMBER

Hermes

จำเฉพาะความรู้ที่ผ่าน Memory Gate เช่น decision, root cause, วิธีแก้, regression และ skill ที่ใช้ซ้ำได้

COMMUNICATE

OpenClaw

จัดการ agent/session communication สำหรับเหตุการณ์สำคัญ ไม่ใช้แทน event bus ของ backend ทุกเหตุการณ์

MEASURE

Harpoon

วัด performance ของเว็บจริงและเปรียบเทียบก่อน/หลัง เป็นหลักฐาน ไม่ใช่ verifier เพียงตัวเดียว

Definition of Done

OMP หรือ LLM ห้ามประกาศว่างานเสร็จจากการประเมินของตัวเองเพียงอย่างเดียว

Verification Gate

✓ Build
✓ Unit Tests
✓ Integration
✓ Browser Test
✓ ECC Review
✓ Security
✓ Harpoon
✓ Regression

Source of Truth

  • Git = ความจริงของ source code
  • Database = ความจริงของ task/state/evidence
  • Tests = functional evidence
  • Harpoon = performance evidence
  • Hermes = agent memory ไม่ใช่ฐานข้อมูลหลัก
  • OpenClaw = agent communication ไม่ใช่ low-level event bus

V0.1 Acceptance

เป้าหมายแรก: จากมือถือสั่งงานหนึ่งงาน แล้วระบบแก้ repo, รัน, ทดสอบ และแสดง preview กลับมาได้จริง

เส้นทางงานขั้นต่ำ

  1. User ส่ง task ผ่าน Web UI
  2. Backend สร้าง Task ID และ workspace
  3. API วิเคราะห์ task และสร้าง instruction
  4. OMP อ่าน/แก้ repository
  5. รัน build + tests
  6. เปิด isolated live preview
  7. แสดง changed files, logs และ test result
  8. เมื่อผ่าน gate จึงอนุญาต commit/PR
